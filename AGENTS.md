# AGENTS.md

Treeva is a Python CLI (Typer + Rich) that scans a directory and produces
structure + code metrics: language distribution, LOC/comment/blank-line
breakdowns, symbols, and marker-based per-directory AGENTS.md files.
Pure Python + tree-sitter; no services.

## Setup and commands

- Manage everything with uv. `uv sync` installs env + dev tools (mypy, pytest, ruff). Python is pinned to 3.14 via `.python-version` (project requires 3.14+).
- Run the CLI through `uv run treeva` — entrypoint is `treeva.cli:app` (`[tool.uv] package = true`). This is a `src/`-layout package; always go through `uv run`.
- Commands: `analyze <path>` (full analysis), `inspect <path>` (file or dir metadata; replaced the old `dir`/`file` commands), `agents <path>` (`--generate` default / `--update` / `--remove`).
- Smoke test after changes by running `uv run treeva analyze <scratch-dir>` on a copy, not this repo.

## Architecture

- Pipeline (`analysis/analyzer.py`): `dir_walker` → `file_info_from_path` → `TreeSitterAnalyzer` → `MetricsAggregator` → `AnalysisResult`. `UnsupportedLanguage` → counted as ignored; other failures are logged and counted in `ScanMetadata.failed_files`; the scan continues.
- `scanners/dir_walker.py` prunes excluded subtrees by mutating `dirs[:]` in place during `Path.walk`. Exclusions are a union (`UnionExclude`): `DEFAULT_EXCLUDES` + target `.gitignore` + CLI `--exclude` patterns.
- New CLI commands: create `cli/commands/<name>.py` exposing `register(app)`, then wire it in `cli/commands/__init__.py` `register_commands`.
- Models are pure dataclasses in `models/`; logic lives in `analysis/`, `scanners/`, `generate/`. Library code must never call `sys.exit()` — raise exceptions, let the CLI layer handle them.
- Style: full type hints, `from __future__ import annotations`, docstring on nearly every function (Args/Returns/Raises/Notes), 79 cols.

## Gotchas

- **AGENTS.md is both input and output.** Files named `AGENTS.md`/`AGENTS.md.bak` are excluded from scans (`constants/excludes.py`). `treeva agents` manages per-section marker blocks (`<!-- Start - Generated By Treeva [<section>], ... -->` … `<!-- End - Generated By Treeva -->`); edits outside markers survive, and `--section/-s` limits generate/update/remove to named sections (repeatable, comma-separated, `all` default). Section classes live in `generate/agents/sections/` and are registered via `generate/agents/sections/__init__.py`'s `ALL_SECTIONS`. A markerless hand-written AGENTS.md triggers an interactive prepend prompt in `cli/commands/agents.py` — expected behavior, not a bug.
- **Adding a tree-sitter language requires touching 4 places**: grammar dependency in `pyproject.toml`, `_LANGUAGES` in `analysis/treesitter/grammars.py`, `TREE_SITTER_GRAMMAR_MAP` in `analysis/treesitter/analyzer.py`, and a `NODE_KIND_MAP` entry in `analysis/treesitter/mapping.py` (hand-curated node-type sets — metrics are only as good as these).
- `git` analysis shells out to `git log --all --numstat` (30 s timeout) and silently degrades to empty on non-repo paths — do not treat empty results as a bug.
- Commit convention: `<type>(<scope>): <summary>` — type one of feat/fix/docs/style/refactor/perf/test/chore, summary ≤ 50 chars, lowercase, no trailing period; body wrapped at 72 chars.
- Stale config, leave as-is: `[tool.ruff] target-version = "py311"` and the `3.12`/`3.13` trove classifiers vs `requires-python = ">=3.14"`.
- `TODOS.md` and `.zed/` referenced in old generated docs no longer exist on disk.
